根目录作为 pnpm workspace 的编排层：pnpm-workspace.yaml 声明 vendor/*、packages/*/*、native/landlock-run、apps/*、website、examples、python/sdk-runtime 等成员，并通过 linkWorkspacePackages + overrides 将 @deepseek-ai/cosmokit、@deepseek-ai/schemastery 等上游框架指向本地 vendor 源码；package.json 的 scripts 是跨子模块的统一入口，build/test/lint/release 等命令按依赖顺序串联 apps、packages、native、website 等子模块的构建与验证。

- 构建链路：`build:lib:host` 与 `build:lib:client` 分别用 tsc -b + tsdown 产出 host/client 产物，再由 `build:web` 驱动 apps/cli 与 Web 前端；`hygiene` 串联 knip、publint、workspace constraints、license/invariant 校验。
- 测试链路：vitest.config.ts 定义 thread-safe / process-bound 两个 project，以 per-file 100% 覆盖率门控覆盖 packages/apps/examples/scripts 下的所有 spec，并按平台（win32）与 pwsh 可用性动态排除；snapshot/web/perf/stress 等独立配置文件由根脚本分发。
- 质量门禁：scripts/run-gates.ts 聚合 check-all / ci-* 等 CI 阶段，scripts 下大量 verify-* 脚本对 cordis.yml、导出 JSDoc、模块图、翻译配对、第三方声明等进行契约级检查。
- 发布链路：release:* 系列脚本负责 bump、verify、pack、publish，并将 native/landlock-run 的 musl 静态二进制与 python_sdk 的 wheel 纳入同一发布流。
- 工作区约束：allowBuilds 白名单仅允许 esbuild、lefthook、node-pty、koffi 等经过审查的构建脚本；patchedDependencies 对 node-pty 打补丁；peerDependencyRules 锁定 TypeScript 版本范围，保证各子模块类型一致。
