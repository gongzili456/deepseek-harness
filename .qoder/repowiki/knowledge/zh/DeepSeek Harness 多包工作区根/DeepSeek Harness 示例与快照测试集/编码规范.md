- 每个示例通过独立的 `cordis.yml` 声明插件树，并以同名 `*.cordis.snapshot.yml` 文件提供快照覆盖件，由测试框架在 `DSH_SNAPSHOT` 下自动加载。
- 快照场景以 `tests/snapshots/<name>/` 为单位组织，固定包含 `input.json`、`session.jsonl`、`stdout.expected.jsonl`，需要时附加 `system-prompt.expected.md` 与 `tool-schemas.expected.json`。
- 测试通过 `defineAcpSnapshotSuite`/`Scenario[]` 表驱动多场景，而非为每个用例编写独立测试函数，新增场景只需追加一行配置。
- 示例配置使用 `!!js` YAML 标签内联表达式读取 `process.env`，将部署开关（如权限模式、压缩格式、工作目录）集中在 cordis.yml 中声明。
- 子 agent 通过 `subagent-spawn-in-process`/`subagent-fork-in-process` 两种 provider 暴露 `spawn` 与 `fork` 工具，并在 cordis.yml 中以不同 `backgroundMode`（continuable/one-shot）区分生命周期。
- 文件系统访问统一走 `dsh-fs-sandbox` + `dsh-sandbox-policy` 组合，读写策略由 `DSH_PERMISSION_MODE` 决定，确保同一套场景在不同权限模式下均可运行。
