模块由两个相互依赖的 hatchling 包组成：
- `python/sdk`（`deepseek-harness-sdk`）：对外暴露 `DeepSeekHarness`、`Session`、`RunResult`、`DeepSeekHarnessConfig` 等高层 API（`api.py`），内部通过 `client.HarnessClient` 以 JSON-RPC 2.0 协议与子进程通信，使用 `queue.Queue` + 多线程（reader/stderr 线程）实现请求/通知/响应的并发收发；`models.py` 定义 `Notification`、`IncomingRequest`、`InitializeResponse` 等 Pydantic/dataclass 数据模型；`errors.py` 定义 `HarnessError` 及其子类 `TransportClosedError`、`SdkProtocolError`、`JsonRpcError`。
- `python/sdk-runtime`（`deepseek-harness-runtime-bin`）：不暴露业务逻辑，仅作为“载体包”在构建期注入平台特定的单文件 Node 可执行二进制（`dsh-jsonrpc-agent-pkg-<platform>-<arch>`）和默认配置 `runtime/cordis.yml`；其 `__init__.py` 提供 `resolve_bundled_launch_args()`、`bundled_runtime_path()`、`bundled_default_config_path()` 等查找函数，并通过 `hatch_build.RuntimeBuildHook` 强制 wheel-only 构建、校验平台清单 `platforms.json` 与可执行文件权限。
依赖方向单向：`sdk` 通过可选 import 调用 `sdk-runtime` 解析运行时路径；当未安装 `deepseek-harness-runtime-bin` 时抛出明确错误提示。SDK 通过环境变量 `DSH_CWD`、`DSH_SESSION_ROOT`、`DSH_CORDIS_CONFIG`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 向子进程注入配置，并在收到 `subagent.started`/`subagent.finished` 事件后维护父子 session 树，使 `subscribe_session_notifications` 能自动转发子 agent 通知给父订阅者。
