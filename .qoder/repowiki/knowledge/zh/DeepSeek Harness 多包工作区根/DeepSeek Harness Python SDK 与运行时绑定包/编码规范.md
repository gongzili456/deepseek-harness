- 配置类统一使用 `@dataclass(slots=True)` 声明（如 `DeepSeekHarnessConfig`、`RunResult`、`HarnessConfig`、`Notification`、`IncomingRequest`）。
- JSON-RPC 响应通过 Pydantic `BaseModel` 进行强类型校验（`InitializeResponse`、`_SessionPromptResponse`、`_ShutdownResponse`），并由 `request()` 统一包装 `model_validate`。
- 资源生命周期采用上下文管理器模式（`__enter__`/`__exit__`）管理 `HarnessClient`、`DeepSeekHarness`、`NotificationSubscription` 的启动与关闭。
- 异步 I/O 通过 `threading.Thread` + `queue.Queue` 实现：独立的 reader/stderr 线程读取子进程输出，主线程通过队列与 waiter 协作完成超时与异常传播。
- 运行时定位采用“可插拔 + 回退”策略：优先使用 `runtime_bin`/`bridge_bin` 覆盖，否则尝试 `deepseek_harness_runtime.resolve_bundled_launch_args()`，失败时抛出包含获取指引的 `FileNotFoundError`。
- 错误体系继承自统一的 `HarnessError` 基类，按故障域拆分为 `TransportClosedError`、`SdkProtocolError`、`JsonRpcError`，便于上层区分处理。
