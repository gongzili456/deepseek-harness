本模块由三个相互独立的子包族组成，均作为 Cordis 插件或协议库对外暴露：
- `packages/mcp/mcp-client`：实现 `@deepseek-ai/dsh-mcp-client`，通过 `connection.ts`/`transport.ts` 以 stdio 或 Streamable HTTP 连接外部 MCP server，将发现的 tool 以 `mcp__<serverName>__<rawName>` 命名注册到 `ctx.tools`；`tools.ts` 负责参数/结果编解码，`invariant.ts` 提供运行时断言。
- `packages/hooks/hook-protocol`：纯协议库 `@deepseek-ai/dsh-hook-protocol`，定义 matcher、stdin/stdout codec、多 hook 输出合并、detached 运行与 `hook/*` 事件追加，被 `hooks-claude-code` 与 `hooks-codex` 两个具体桥共享。
- `packages/hooks/hooks-claude-code` / `hooks-codex`：分别把 Claude Code 与 Codex 的 `hooks.json` 映射到 harness 的 `agent/session-start`、`agent/pre-step`、`tools/pre-execute`、`tools/post-execute`、`agent/turn-stopping`、`subagent/start|end` 等扩展点，各自维护 payload 构造与配置解析。
- `packages/extensions/cordis-host-runner`：Host 端动态插件服务 `DynamicCordisRunnerService`（继承 `TypertRemoteService`），维护 `registry.ts` 中的 Plugin/Package 不可变定义、`sandbox.ts` 中 VM 隔离执行 Host 代码、`lifecycle.ts` 启动 Fiber，并通过 `@Remote(...)` 装饰器暴露 `run/runHostHalf/invoke/stop/...` 给 Client 调用。
- `packages/extensions/cordis-client-runner`：Browser 端对应半部，`client/orchestrator.ts` 编排 define→approve→run 流程，`guard.ts` 做客户端安全校验，`evaluator.ts` 在浏览器中执行 Client 代码并上报渲染失败。
- `packages/extensions/tool-cordis`：向 Agent 暴露 `cordis_define`/`cordis_run`/`cordis_stop` 等工具，驱动 host-runner 生命周期。
- `packages/extensions/ui-cordis`：React 卡片（`CordisPanel`/`CordisRunRow`/`CordisDefineRow`），通过 `dsh.client` 注入依赖并在 `dsh` 字段声明 web 平台打包清单。
依赖方向严格单向：`hooks-claude-code`/`hooks-codex` → `hook-protocol`；`tool-cordis` → `cordis-host-runner`；`ui-cordis` → `cordis-client-runner`；`mcp-client` 仅依赖 `@modelcontextprotocol/sdk` 与内部 transport。
