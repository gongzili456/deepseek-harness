模块由三个子包构成清晰的层次：
- `session-persistence` 提供抽象层：`SessionPersistence` 抽象类在 `src/index.ts` 中声明 `locate/create/append/load/inspect/readFrom/list/listSnapshots` 等核心 API；`coordinator.ts` 实现跨后端的写路径编排（批缓冲、序列化、adopt、crash repair、dispose 协调），并通过 `PersistenceBackend<TornMarker>` 接口与具体后端解耦；`revision.ts` 用 `Branded` 类型封装源相关 revision；`preparations.ts` 与 `write-behind.ts` 分别处理冷启动准备缓存与写回延迟。
- `session-persistence-jsonl` 是文件型后端：`JsonlSessionPersistence` 以每个 session 一个 append-only JSONL 文件（可选 zstd 压缩）存储，通过 `format.ts` 编码 header+event lines，`zstd.ts` 做帧级压缩/解码，`win32.ts` 处理 Windows 原子发布；它实现 `PersistenceBackend<JsonlTornMarker>`，将 torn tail 的字节偏移与恢复事件作为 opaque marker 交给 coordinator 修复。
- `session-persistence-sqlite` 是关系型后端：`SqliteSessionPersistence` 使用 Node `DatabaseSync` 打开单库，`schema.ts` 维护 `persistence_state/sessions/events` 三表及 `SCHEMA_VERSION`，通过 `loadStoredFrom` 提供 seek-capable 后缀读取；torn marker 为 seq 号，`commitRepair` 在一个事务内删除尾部并插入 closers。
依赖方向单向：两个后端 → `@deepseek-ai/dsh-session-persistence`（抽象 + coordinator）→ `@deepseek-ai/dsh-session`（事件模型），彼此互不依赖。
