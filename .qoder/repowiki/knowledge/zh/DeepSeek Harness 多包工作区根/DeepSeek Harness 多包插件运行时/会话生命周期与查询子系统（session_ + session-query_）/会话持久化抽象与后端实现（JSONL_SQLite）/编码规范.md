- 每个后端以 `static Config` 配合 Schemastery schema 声明配置项，并在构造函数中对未走 schema 的程序化构造提供默认值回退。
- 所有读路径接受可选 `AbortSignal`，并在关键 I/O 前调用 `signal?.throwIfAborted()` 以支持取消。
- 后端通过实现 `PersistenceBackend<TornMarker>` 接口暴露存储原语，torn tail 的具体语义（字节偏移 / seq）对 coordinator 完全透明。
- revision 通过 `SessionPersistenceRevision(value)` 工厂函数包装成 branded string，JSONL 端基于 dev/inode/mtime/ctime，SQLite 端基于 storeIdentity/incarnation/revision。
- 写路径统一委托给 `PersistenceCoordinator`，后端仅实现 `appendBatch`/`commitRepair` 等最小持久化钩子，避免重复编排逻辑。
- 错误分类明确区分 `SessionPersistenceCorruptionError`（数据损坏）与 `SessionFormatUnsupportedError`（格式版本不受支持），后者携带 `location` 以便定位原始日志。
