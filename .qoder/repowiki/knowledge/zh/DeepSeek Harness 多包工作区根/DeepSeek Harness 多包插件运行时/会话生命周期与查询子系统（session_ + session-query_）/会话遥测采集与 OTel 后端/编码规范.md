- 遥测记录统一建模为 `SessionTelemetryRecord`（channel/time/severity/attributes/body），ledger 与 ops 通道共用同一结构体，仅通过 channel 字段区分。
- 后端通过继承 `SessionTelemetryBackend` 并实现 `emit/shutdown`（可选 `flush`）来接入采集侧，共享策略通过 `sharing` 属性对外披露。
- 采集路径中所有回调均用 `contain()` 包裹 try/catch，使单个监听器抛出仅丢弃该条记录而不阻塞后续 cordis 订阅者。
- 部署级数据清洗通过 `ctx.waterfall('session-telemetry/record', record, () => record)` 扩展，默认 next 透传，无监听器时原始记录直达后端。
- OTel 后端按记录 channel 分流到两条独立 logger（`@deepseek-ai/dsh-session-telemetry-otel` 与 `.../ops`），并以 Resource 属性携带 service.name/version/user.id 等进程级标识。
- 配置对象使用 schemastery schema 声明顶层字段，运行时额外校验放在构造函数内，以便错误消息能引用具体字段名。
