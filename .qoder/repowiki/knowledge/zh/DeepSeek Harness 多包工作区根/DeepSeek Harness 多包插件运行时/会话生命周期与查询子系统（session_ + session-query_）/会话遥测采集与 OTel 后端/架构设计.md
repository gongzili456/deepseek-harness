模块由两个协作的 npm 包组成：`session-telemetry` 定义采集侧契约（`SessionTelemetryBackend` 抽象类、`SessionTelemetrySink` 接口、`SessionTelemetryRecord` 逻辑记录模型），并由 `SessionTelemetryCoordinator` 实现——它订阅 cordis 上下文中的 `session/created`、`session/event`、`session/disposed`、`session/flush` 以及 `agent/error` 总线，对 `assistant/chunk` 做首块去重投影，按事件类型推导 severity，通过 `ctx.waterfall('session-telemetry/record')` 执行部署挂载的脱敏规则，再以 `WeakMap<Session, number>` 维护 handoff cursor 以支持 HMR 重新 adopt 时不重复发送历史；`session-telemetry-otel` 是该契约的一个具体后端 `OpenTelemetrySessionBackend`，根据配置模式（`FULL` / `FEEDBACK_ONLY` / `DISABLED`）选择 live/on-demand 采集或丢弃所有 emit，使用 OTel JS SDK 的 `LoggerProvider` + `BatchLogRecordProcessor` + `OTLPLogExporter` 将记录映射为两条 logger（`@deepseek-ai/dsh-session-telemetry-otel` 与 `/ops`），并在 shutdown 上以超时保护等待 provider 完全退出。依赖方向单向：otel 包依赖 telemetry 包暴露的 seam，telemetry 包仅依赖 cordis/session/agent 的类型，不感知任何传输细节。
