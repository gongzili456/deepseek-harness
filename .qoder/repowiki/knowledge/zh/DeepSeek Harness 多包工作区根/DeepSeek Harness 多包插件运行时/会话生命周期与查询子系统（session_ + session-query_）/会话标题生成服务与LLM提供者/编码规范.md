- 提供者通过 `ctx.sessionTitle.register({ id, automatic, generate })` 以对象形式注册，其中 `automatic` 限定为 `'first-prompt' | 'all-prompts'` 两种枚举模式。
- 所有外部输入（配置、provider 对象、provider 返回结果）在进入服务前均通过显式的 `validate*` / `assert*` 函数做白名单校验并抛出带前缀的错误消息。
- 并发安全采用 revision 递增 + AbortController 组合：每次新工作通过 `supersede` 中止旧 active 工作并递增 revision，`assertCurrent` 在关键路径检查 revision/session/provider 是否仍匹配。
- LLM 驱动的提供者统一通过 `registerSessionTitleLlmProvider` 注册，仅暴露 `selectMessages` 选择器差异，共享系统提示、JSON 帧化、超时与 finish reason 处理逻辑。
- Log-only 事件（`session/title`、`session/title-llm-request`）通过模块声明扩展 `SessionEventMap` 注入类型，而不引入运行时依赖，保持纯类型入口。
- 配置 schema 使用 `@deepseek-ai/schemastery` 的 `z.object({...}).required()` 声明，并通过 `SessionTitleLlmConfigFields` 等常量在多个插件间复用字段校验器。
