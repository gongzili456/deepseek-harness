模块以两个独立的 Cordis 插件形式暴露：`src/index.ts` 导出主插件 `session-checkpoint-policy`（注入 `llm`、`sessionPersistence`、`sessions`、`tools`），在三个关键水闸处拦截并调用 `ctx.sessions.flush(session)` 后再放行下游——`llm/stream` 在构造模型流之前、`tools/execute` 在执行顶层工具体之前、`agent/pre-step` 在每个新请求开始前；若 flush 失败则 fail-closed，阻止后续 adapter/tool 执行，并在工具取消场景返回带 `TOOL_ABORTED_BEFORE_DISPATCH` 的错误结果。`src/invariant.ts` 提供同包名下的 companion 插件 `session-checkpoint-policy-invariant`，仅向 `@deepseek-ai/dsh-invariants` 注册空安装器以声明该包对持久化顺序的无状态所有权。依赖方向单向指向 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-agent` 与 `@deepseek-ai/dsh-session-persistence`，不持有可变状态，所有持久化通过 session 对象完成。测试位于 `tests/`，使用自定义 `TestPersistence` 与 `RecordingAdapter` 验证 flush 时序、取消与失败路径以及 fiber 生命周期。
