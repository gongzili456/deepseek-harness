本模块由四个并列的 @deepseek-ai/dsh-* 子包组成，围绕 `@deepseek-ai/cordis` 的 Context/Service/Events 构建，依赖方向自上而下为 tools → system-prompt → session → scope。

- `scope`（最底层）：实现作用域键 `ScopeKey`、父子链 `bindScopeParent`/`scopeChainOf`、通过 `WeakMap` 维护 parent 关系并禁止环；`createScope` 用 Cordis fiber 作为作用域生命周期边界，`scopeTarget` 在 Cordis filter 中按祖先链向上匹配以实现“父作用域接收子作用域事件”的路由语义；`store.ts` 提供 `AnonymousEntries`/`NamedEntries`/`ScopedLayers` 用于按作用域叠加注册表。
- `session`：以 `Session` 类为核心，内部维护 append-only 的 `SessionEvent[]` 日志，并通过 `SurfaceManager` 维护有序 surface 节点；`SessionStore` 是 Cordis Service，暴露 `prepare/enter/announce` 三段式生命周期，配合 `scopeTarget(session, scopeOf(ctx))` 将 `session/event`、`session/created`、`session/disposed`、`session/flush` 等事件做作用域过滤；所有事件数据经 `snapshotJsonValue` 深拷贝 + `deepFreeze` 保证不可变与 JSON 可持久化；`surface.ts`、`request-header.ts`、`chunk-rows.ts`、`repair.ts`、`preparation.ts`、`json.ts` 分别承担消息推导、请求头折叠、存储分块、中断修复、会话准备与 JSON 序列化。
- `system-prompt`：`SystemPrompt` 服务使用 `ScopedLayers` 管理 sections/context/tools/variables 四类注册，按 order 排序并在 `assemble()` 中合并全局与作用域层，运行 `system-prompt/assemble` waterfall 后强制恢复 complete section；变量插值严格校验 `{{name}}` 语法与已注册名；导出 `PERSONA_SECTION`/`PERSONA_ORDER` 等常量供部署配置覆盖。
- `tools`：`ToolRuntime` 服务维护 `ToolLayer`（工具定义、限制、守卫、呈现模式），通过 `ctx.systemPrompt.tools(...)` 把可见 schema 注入提示装配；执行路径为 `tools/pre-execute` → 守卫 → `tools/execute` around-wrapper → 工具体 → `tools/post-execute` → `tools/result` emit，全部支持作用域过滤；内置 `run_code` 传输器与 TypeScript/Python SDK 渲染器，支持 native/code/both 三种模型可见模式；`schema.ts`、`json-schema.ts`、`ts-types.ts`、`py-types.ts`、`presentation.ts`、`code-mode.ts`、`testing.ts` 分别负责参数 schema、JSON Schema 校验、SDK 代码生成、UI 呈现意图与测试夹具。

各包均通过 `declare module '@deepseek-ai/cordis'` 扩展 `Context` 接口（`sessions`、`systemPrompt`、`tools`）并以 `@dshScopeScan unsupported` 注释标注作用域扫描不支持的事件。
