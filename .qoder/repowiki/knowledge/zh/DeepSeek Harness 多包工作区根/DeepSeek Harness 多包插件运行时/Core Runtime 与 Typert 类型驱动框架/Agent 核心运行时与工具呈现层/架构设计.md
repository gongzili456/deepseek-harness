模块由三个相互独立的 Cordis 插件包组成，按职责分层：
- `@deepseek-ai/dsh-agent`（agent）：核心运行时。`src/index.ts` 导出 `AgentRegistry`（继承 `Service`），维护进程内 Agent 实例 Map、创建工厂槽位和基于 `AsyncLocalStorage` 的发起者调用链；通过 `enter/announce/register` 三阶段发布 Agent，并通过 `ctx.events` 广播 `agent/created`、`agent/disposed`、`agent/status`、`agent/inbox/*`、`agent/session-start` 等事件。`runtime-types.ts` 通过模块扩展声明 `Cordis.Events` 与 `TypertLookupMap`，定义 `Agent` 句柄、`AgentOptions`、`PreStepDecision`、`RequestErrorAction` 等公共类型。`dispatch.ts` 提供 `agentCarrier`/`agentEvents`/`emitAgentEvent` 将 agent 注入为事件 subject 并绑定 scope carrier。`inbox.ts`、`consumed-work.ts`、`model-selection.ts`、`types.ts`、`invariant.ts` 分别实现消息投递、已消费工作追踪、模型选择策略、通用类型与不变量。
- `@deepseek-ai/dsh-agent-default-model`：作为独立 Service (`AgentDefaultModelConfig`) 暴露 `currentSelection()`/`saveSelection()`，通过 `dsh-settings` 的 `installSettingsSection` 把持久化配置投影为 `ModelSelection`，供上层入口在缺少 session 级模型时回退使用。
- `@deepseek-ai/dsh-agent-tool-presentation`：以 Cordis 插件形式（`apply(ctx, config)` + `inject = ['tools']`）根据 `mode`（`native`/`code`/`both`）调用 `ctx.tools.presentAs()` 声明该 composition 范围内所有 Agent 的工具呈现方式；对 `code` 模式通过 `ctx.inject(['codeRuntime'], ...)` 懒等待代码运行时可用。
依赖方向单向向下：default-model 与 tool-presentation 仅依赖 `dsh-agent` 的类型与 `@deepseek-ai/cordis`，不反向引用；三者均通过 workspace peerDependencies 耦合到 dsh-session、dsh-llm、dsh-scope、dsh-tools、dsh-system-prompt 等底层能力。
