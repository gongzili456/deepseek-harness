模块以 Cordis 插件形式组织，`src/index.ts` 导出 `apply(ctx, config)` 作为主入口，声明依赖 `typert`（注册表）和 `loader`（Loader 服务），通过 `ctx.on('internal/plugin')` 订阅 Loader 的 fiber 生命周期事件；激活阶段先对当前所有 entry 执行一次增量扫描，后续每次 mount/unmount 将 entry name 加入 dirty set 并通过 microtask 批量 flush，实现每 entry 的增量注册/注销。

内部职责分层清晰：
- 解析层 `resolveArtifact` 使用 `createRequire(ctx.baseUrl)` 定位 package.json 并解析 `exports["./typert"]`（支持字符串与一层 conditional default），结果按包名缓存且永不失效。
- 导入层 `loadManifest` 动态 `import()` 目标路径并将 TYPERT 模块实例按包名去重缓存。
- 校验层 `validateTypertManifest` 是模块/文件边界，用一系列 `require*` 辅助函数（`requireObject`/`requireArray`/`requireString`/`requireDocumentation`/`requireMembers`/`requireTypes`/`requireInvocation`/`requireStrictCodec`）对 manifest 做深度结构校验，错误消息统一以 `typert-loader: ${pkgName} ...` 前缀命名缺陷来源。
- 协调层 `processOne`/`flush` 管理 pending/registered 状态机，保证并发 import 期间 entry 可能已卸载或重复注册的竞态安全。

`src/invariant.ts` 提供同包的 invariant 伴生插件 `typert-loader-invariant`，仅向 `@deepseek-ai/dsh-invariants` 登记包所有权，无运行时逻辑。`package.json` 通过 `exports` 同时暴露 `.` 与 `./invariant` 两个入口，并以 workspace peerDependencies 绑定 cordis、dsh-typert-registry、schemastery 等运行时依赖。
