本模块由四个协作包构成 Typert 的完整生命周期：
- generator（构建期）：通过 TypeScript 程序分析扫描 host/client 业务面，产出 FaceModel，再由 renderer/emitter/tsdown-plugin 生成运行时 JS、类型声明与 Zod schema。
- protocol（共享契约）：提供编译器无关的 RPC 类型、Remote/RemoteScope 装饰器与服务到网关绑定，被 generator 生成的代码与 loader/registry 共同消费。
- registry（运行期）：以 ctx.typert 暴露原子化的 Schema、反射元数据与本地/远程描述符注册、查询、订阅与 JSON Schema 投影能力，是 loader 与宿主应用的唯一运行时入口。
- loader（启动期）：作为 Cordis 插件消费 ctx.loader 与 ctx.typert，扫描挂载入口包的 ./typert 贡献并自动注册到 registry。
跨包协作流程为：generator 在构建时产出依赖 protocol 的类型与 schema → 应用启动时 loader 发现并调用 registry 完成注册 → 运行时通过 protocol 提供的 Remote 装饰器发起跨进程调用，所有三方均围绕 registry 的同一份元数据进行读写。
