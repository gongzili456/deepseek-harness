模块以 `index.ts` 中的 `AgentLoop`（继承自 `@deepseek-ai/cordis` 的 `Service`）作为插件入口，对外暴露 `create` / `createAgent` / `resume` 三种实例化路径，并通过 `FactoryOwnership` 统一跟踪活跃 agent 的 teardown 和工厂级启动任务，在 fiber 卸载时通过 `AbortController` 中止所有进行中的创建/恢复流程。

核心驱动位于 `agent.ts` 的 `ReactLoopAgent`：维护 `idle | maintenance | running` 三态机，通过 `inbox` 接收 `send/followup/steer/inject` 输入，在 `turn()` 中打开 `turn/start` 事件，循环调用 `preStep` 组装系统提示与上下文，再进入 `step()` 构建请求、流式消费 LLM 响应、追加 `assistant/chunk` 与 `assistant/message`；当出现 tool-call 块时委托 `tool-calls.ts` 的 `executeToolCalls` 执行。

`tool-calls.ts` 是独立的调度器：按模型顺序将工具分组为独占屏障或并行池（受 `maxParallelToolCalls` 限制），通过 `ctx.tools[TOOL_RUNTIME_SCHEDULER]` 的 prepare/dispatch/finalize 协议执行，保证结果按模型顺序提交到 session，并在 abort 时为未启动调用写入合成错误结果以维持回放一致性。

辅助层：`runtime-context.ts` 的 `RuntimeContextProjection` 基于 session 历史追踪最近一次 runtime context snapshot，避免重复写入；`invariant.ts` 注册一个全局 `llm/stream` 监听器，校验 loop 构造的请求必须 frozen、携带 sessionId、且消息可经 `session.deriveMessages()` 重放重建；`constants.ts` 提供默认并行度常量。

依赖方向单向向外：本模块依赖 `dsh-agent`、`dsh-llm`、`dsh-session`、`dsh-scope`、`dsh-tools`、`dsh-system-prompt`、`dsh-settings`、`@deepseek-ai/cordis`，不反向被这些包引用；通过 `Context` 扩展注入 `agentLoop` 服务与 `configuredAgentIdentities` 键，由上层 launcher 装配。
