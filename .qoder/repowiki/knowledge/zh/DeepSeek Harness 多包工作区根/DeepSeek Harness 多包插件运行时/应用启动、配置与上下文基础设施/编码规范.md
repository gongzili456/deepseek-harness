- 每个包通过 `declare module '@deepseek-ai/cordis' { interface Context { ... } }` 扩展 Context 接口，将服务键名（如 `settings`、`workspaceRegistry`、`cmdlineArgs`、`sessionReferenceResolver`）声明为宿主提供的属性。
- 服务类继承 `Service` 并在构造函数中调用 `super(ctx, '<service-name>')`，通过 `static inject = [...]` 声明依赖的服务键，在 `[Service.init]` 中完成初始化。
- 配置对象统一使用 `schemastery` 的 `z.object({...}).default(...)` 定义，并在插件构造或 `apply` 入口处对数值进行 safe integer / 范围校验后抛出具名错误。
- 每个包都附带 `src/invariant.ts` 与 `tests/invariant.spec.ts`，用于断言公共 API 的行为不变式（如 settings 的 deepEqualJson 与实现一致）。
- 写路径采用“先验证再入队”的模式：settings 的 `update/replace/mutate` 先做 JSON-shape 克隆与 schema 校验，再串入 per-namespace 写队列；workspace 的所有写方法经 `enqueueOperation` 串行执行并在失败时回滚。
- 对外暴露的错误类均带有稳定 `code` 字段（如 `SETTINGS_CONFLICT`、`SESSION_REFERENCE_*`、`WorkspaceUnknownSessionError`），便于 wire 层映射到宿主错误分类。
