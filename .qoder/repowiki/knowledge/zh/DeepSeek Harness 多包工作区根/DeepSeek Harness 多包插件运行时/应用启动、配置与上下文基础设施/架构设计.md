本模块由四个并列的包组成，均基于 `@deepseek-ai/cordis` 的 Service/Context 模型扩展宿主能力：
- `boot/app-boot`：应用入口胶水，负责加载 `.env`（按进程 > 项目目录 > Harness home 分层合并并拒绝 bootstrap-only 变量）、解析快照模式下的配置文件路径、挂载根 `cordis:include` 并通过 `applyEntryPatches` 应用可选 patch 层；暴露 `boot()`、`installFailLoud()`、`assertEntriesActivated()`、`watchUserPatches()`、`renderConfigDump()` 等启动期 API，并通过 `mountRootInclude` 将 Include/Group 作为 Loader 内置项注入。
- `boot/cmdline`：仅暴露 `CmdlineArgs`/`AppExit` 两个宿主契约，通过 `provideCmdline` 把命令行参数和受控退出注入 Context，再由 `parseCmdline` 用 commander 解析，使 CLI 语义完全归属应用插件而非 launcher。
- `settings/settings` + `settings/settings-file`：抽象出 `SettingsProvider`（命名空间注册、schema 校验、base/user 三层合并、序列化写队列、revision 冲突检测、`settings/document-updated` 事件），`settings-file` 实现基于本地文件的持久化并提供 watcher/HMR 重读。
- `workspace/workspace`：以 `WorkspaceRegistry` 服务维护持久化的工作区登记、会话归属与显示顺序，依赖 `storageDomain` 与 `sessionPersistence`，在 `Service.init` 中完成 pending mutation 恢复、header 索引重建与 live session 同步，所有写操作经 `enqueueOperation` 串行化并带回滚。
- `context/*`：一组独立的 Cordis 插件，各自通过 `ctx.on('agent/pre-step' | 'tools/result' | 'session/event')` 或 `ctx.effect` 向 agent inbox 注入上下文：`agent-instructions` 读取 AGENTS.md 基线并按文件变更增量投影；`session-reference` 跨会话抓取快照并受字节预算限制；`time-context` 在请求阶段注入带时区与耗时信息的时间戳；`tmux-context` 提供 tmux 会话信息。每个子包自包含 schema、类型、invariant 与测试，对外只暴露一个 `apply(ctx, config)` 或 `Service` 类。
依赖方向单向向外：各上下文插件依赖 `dsh-agent`/`dsh-session`/`dsh-llm` 等上层领域包，不反向引用 boot/settings；boot 通过 Cordis 的 loader/include 机制组合这些插件。
