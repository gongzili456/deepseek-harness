本模块由四个相互协作的子包构成，形成从 UI 到宿主再到外部自动化客户端的完整调用链：
- `packages/host/apiproxy`：定义统一的 RPC 方法契约（`api/rpc-map.ts` 中的 `RpcMethodMap`），每个领域（session、workspace、settings、llm、credentials、jobs、goals、agentPreset、subagents、skills、host）以 `*.schema.ts` + `*.ts` 成对声明 Zod schema 与实现，并通过 `fetch/client.ts` 暴露 `toFetchHandler` 供上层 HTTP 路由转发。
- `packages/host/*`（directory-picker、frontend-static、plugin-inventory、webserver 等）：作为 Cordis 插件挂载到宿主上下文，通过 `apply(ctx, config)` 注册服务或 Web 路由，依赖 apiproxy 提供的 `ctx.apiProxy`。
- `packages/client/connection`：浏览器到宿主的 HTTP+WebSocket 桥，使用 `HostConnectionService` 将 `/api` 请求转发给 apiproxy，并对 `PRIVILEGED_METHODS`（如 settings、credentials、host.pickDirectory）强制 loopback 信任校验；同时提供 MUX/HOST 事件 WebSocket downlink。
- `packages/sdk/{protocol,client,server}`：协议层 `@deepseek-ai/dsh-sdk-protocol` 定义 newline-delimited JSON-RPC 传输与类型；`server` 作为 Cordis 插件监听 stdio 上的 JSON-RPC 请求并驱动宿主 runtime；`client` 是 TypeScript 侧进程启动器，通过子进程 + stdio 驱动 Python 端 SDK。
- `packages/acp/acp`：基于 `@agentclientprotocol/sdk` 的自动化 Agent Client Protocol 服务器，通过 stdio JSON-RPC 暴露 session/new、prompt、cancel 等最小化能力，并将宿主 approval/request 映射为一次性 allow/reject 决策，严格过滤非文本提示内容。
依赖方向单向：acp → dsh-agent/session；sdk/server → protocol；client/connection → apiproxy；apiproxy → 各业务域插件。所有跨进程边界均通过显式 schema（Zod/schemastery）和 RPC map 进行类型与参数校验。
