模块由三个并列子域组成，均基于 @deepseek-ai/cordis 的 Service/Context 扩展：
- packages/llm：核心抽象层 `@deepseek-ai/dsh-llm` 定义 `LlmAdapter` 抽象类、`LlmRuntime` 服务（继承自 Service）、`BlockAssembler`、重试策略、消息/内容类型及 `LlmError` 统一错误体系；通过 `ctx.waterfall('llm/stream', ...)` 暴露可拦截的流式调用入口，并支持 `registerAdapter` / `registerConfigurableProviders` / `registerModelDiscovery` 三种原子化注册句柄（含 `replace` 无锁替换）。`llm-deepseek` 与 `llm-pi-ai` 是两个独立插件包，各自实现 `apply(ctx, config)` 并通过 `installSettingsSection` 监听配置变更，使用 `registration.replace()` / `directory.replace()` 做原子路由切换；两者都通过 `ctx.credentials` 或 `launchEnvironmentOf` 按请求解析 API Key，并复用 `assertUsableApiKey` 校验。
- packages/credentials：`dsh-credentials` 定义 `CredentialProvider` 抽象服务（resolve/describe/set/unset），约定空值即“未配置”；`dsh-credentials-local` 是具体实现，将凭据持久化到本地存储并以事件 `credentials/updated` 广播变更。
- packages/identity：`dsh-anonymous-user-id` 在 `$DSH_HOME/.anonymous-user-id` 中以裸 UUID 行形式持久化每 harness-home 的匿名身份，读写同步且进程内 memo，删除文件即重新生成。
依赖方向单向收敛：llm-deepseek/pi-ai → dsh-llm → dsh-credentials；token-meter 仅消费 dsh-llm 的 BlockAssembler 与 Session 事件做用量估算；各包通过 package.json 的 `exports` 字段精确暴露 `.`、`./invariant`、`./types` 等子路径，保持内部实现不被外部直接依赖。
