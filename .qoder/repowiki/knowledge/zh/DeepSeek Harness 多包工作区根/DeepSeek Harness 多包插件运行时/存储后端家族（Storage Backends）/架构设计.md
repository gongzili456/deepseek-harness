模块以 Cordis 插件体系组织为四个相互依赖的子包，形成清晰的依赖方向：`storage-domain` → `storage` ← `storage-json` / `storage-sqlite`。
- `storage`（`@deepseek-ai/dsh-storage`）是核心枢纽 `Storage` 服务，维护 `BackendRegistry` 与可挂载的 `StorageForms`；通过 `ctx.storage.backend.register(name, backend)` 注册后端，并通过 `mount('domain', facility)` 挂载数据表单；暴露 `KvFacet`/`KvUnit`/`KvUnitDescriptor` 等类型契约与 `storageBackendServiceKey` 生命周期服务键。
- `storage-domain`（`@deepseek-ai/dsh-storage-domain`）在 `ctx.storage` 之上提供 `DomainFacility`，用 `defineDomain` + zod schema 声明表结构与全局值，`open(spec)` 时按路由解析到已注册后端的 `kv.open(descriptor)`，加载快照并逐条校验记录，变更通过 `domain/changed` 事件发布；通过模块扩展把 `domain: DomainFacility` 注入 `StorageForms`，并把自身挂载为 `ctx.storageDomain`。
- `storage-json` 与 `storage-sqlite` 是具体介质实现，各自导出 `name`/`inject=['storage']`/`Config`(schemastery) 及 `apply(ctx, config)`，在 effect 中调用 `ctx.storage.backend.register('json'|'sqlite', ...)`，同时通过 `ctx.provide(storageBackendServiceKey(...))` 暴露后端实例供 domain 层注入。
- JSON 后端以每 unit 一个 `.json` 文件持久化，使用原子写入；SQLite 后端共享单个 `DatabaseSync`，通过 `units` 表做版本戳校验并按 descriptor 动态建表，支持 WAL/rollback journal 模式。
- 错误统一通过各包的 `error.ts` 中的 `StorageError`/`DomainError` 表达，包含 code/detail 以便诊断。
