本模块由三个并列的能力域组成，每个域都遵循“抽象服务定义 + 具体插件实现”的分层：
- LSP 域：`packages/lsp/lsp` 暴露 `ctx.lsp` 服务（`Lsp`），维护扩展名→Provider 路由表并统一抛出带稳定 code 的 `LspError`；`lsp-stdio` 是 stdio 后端，按 workspace 池化 `LspInstance`，通过 `connection.ts`/`framing.ts`/`protocol.ts` 管理子进程生命周期与 JSON-RPC 帧；`tool-lsp` 将 `ctx.lsp` 包装成模型可调用的 `lsp` 工具，负责坐标转换与结果渲染。
- Skill 域：`packages/skill/skill` 暴露 `ctx.skills` 服务（`SkillRegistry`），基于 `@deepseek-ai/dsh-scope` 的 `ScopedLayers` 实现按 scope 分层的 Provider 注册与覆盖，缓存目录级 catalog 并通过 `skills/change` 事件失效；`skill-filesystem` 是本地文件系统 Provider，扫描 `.dsh/skills`、`.agents/skills`、用户目录与 bundled 目录，使用 Chokidar 监听变更并返回 `{ candidates, complete }` 观测；`skill-badge`、`tool-skill` 分别提供徽章与工具封装。
- Compaction 域：`packages/compaction/compaction` 暴露抽象 `CompactionEngine`（`compactIfNeeded`/`compactNow`/`compactRegion`）及 `ManualCompactionError` 分类错误；`compaction-basic` 实现基于 token 计量的压力触发与 context-overflow 恢复，通过 `region.ts`/`summarizer.ts` 选择可压缩区间并调用 LLM 生成摘要；`command-compact` 提供 `/compact` 命令并将 `ManualCompactionError.code` 映射为用户可读结果；`compaction-tool-result-pruner` 作为可选前置步骤在压缩前裁剪工具输出。
依赖方向单向：工具/命令 → 能力服务定义 → 具体实现；各域之间不互相引用，仅通过 Cordis `Context` 注入共享服务（如 `fs`、`subprocess`、`llm`、`tokenMeter`）。
