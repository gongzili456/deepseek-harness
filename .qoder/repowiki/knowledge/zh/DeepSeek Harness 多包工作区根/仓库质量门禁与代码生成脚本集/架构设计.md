本模块是工作区的工具层，所有文件以独立可执行脚本形式存在，通过 `pnpm run <script>` 或 `run-gates` 编排调用，不暴露公共 API。
- 入口编排：`run-gates.ts` 定义 `Mode`（如 `ci-primary`、`ci-static`、`doc-sync` 等），按模式组装 Gate 依赖图并以内置调度器并发执行子进程；每个 Gate 通过 `pnpmScript` / `pnpmExec` 构造 shell-free 的 `node pnpm ...` 调用，避免平台差异。
- 校验脚本对：每个 `.ts` 逻辑实现通常配一个同名 `verify-*` 薄壳 CLI（如 `package-invariants.ts` + `verify-package-invariants.ts`），CLI 仅解析根路径、调用核心函数、打印 violations 并以 exit code 表达结果。
- 生成脚本：`gen-*` 系列（如 `gen-third-party-notices.ts`、`gen-cordis-catalog.ts`、`gen-doc-graphs.ts`）读取 workspace manifest、pnpm-workspace、pyproject.toml 等源，输出 Markdown/JSON 等制品，并由对应 `verify-*` 脚本做 `--check` 比对。
- 共享基础设施：`ts-project.ts`、`markdown.ts`、`jsdoc.ts`、`repo-files.ts`、`slot-walk.ts`、`cordis-walk.ts`、`package-graph.ts` 提供 TS 配置解析、Markdown AST、Cordis/Slot 遍历、包图构建等复用能力，被多个 gate 消费。
- 测试组织：每个脚本旁放置 `*.spec.ts`（Vitest），由 `run-gates` 的 `test` 模式统一执行；快照数据集中在 `scripts/snapshots/` 和 `scripts/fixtures/`。
- 平台适配：`.sh` 脚本（`prepare-ci-bubblewrap.sh`、`wine-windows-gates.sh`、`merge-translation-pairing-driver.sh`、`check-vendor-manifest.sh` 等）封装平台特定命令，保持主流程 shell-free。
- 依赖方向：脚本之间通过相对路径 import（如 `./package-invariants.ts`），不反向引用业务包；对外仅依赖 Node 内置模块、TypeScript、mdast、yaml/toml/spdx 等工具库。
