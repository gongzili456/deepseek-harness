- 所有子模块的测试统一放在各自 tests/ 目录下并以 .spec.ts 结尾，由根 vitest.config.ts 的 include 规则自动发现
- 跨子模块的类型解析统一通过 tsconfig.base.json 的 paths 映射，避免加载已构建 lib 导致单例重复
- 新增 npm 依赖若带有 install/build 脚本必须显式列入 pnpm-workspace.yaml 的 allowBuilds 白名单，否则安装失败
- 质量门禁脚本集中在 scripts/ 下，通过 run-gates.ts 或独立的 verify-*.ts 暴露为 package.json 中的同名命令
- 多语言文档与 README 采用 i18n 配对模式（.yaml 清单 + zh 副本），由 scripts 中的 translation-pairing 脚本校验一致性
- 工作区内依赖通过 workspace:^ 引用，确保开发时直接链接源码而非 node_modules 中的旧版本
