本模块由两个并列的 npm 包组成，均通过 `apply(ctx, config)` 导出插件式入口，使用 `@deepseek-ai/dsh-tools` 的 `defineTool` 注册到 `ctx.tools`，并通过 `ctx.systemPrompt.section` 注入显式调用策略。

- tool-workflow (`@deepseek-ai/dsh-tool-workflow`)：暴露 `workflow` 工具（名称可配置），将用户的 JavaScript 脚本交给 `ctx.workflowEngine.start` 在 worker 线程中运行；通过 `createWorkflowRecorder` 订阅 `workflow/agent-start|agent-end` 事件并写入 `Session`，实现 run/agent 级持久化记录；结果经 `stopReasonError` 映射为 isError 或正常返回 `{runId, agentsStarted, result}`，并以 `generic` 卡片呈现。
- tool-ralph (`@deepseek-ai/dsh-tool-ralph`)：不依赖用户脚本，而是内嵌一段不可篡改的 `RALPH_SCRIPT`（字符串模板），以固定 meta 和 schema 启动 `ctx.workflowEngine`；通过 `requireFreshProvider` 校验子代理提供者必须支持 structured output 且 `inheritsParentContext=false`，确保每轮都是全新上下文；对跨 provider 边界返回的报告用 `readReport` / `readRunResult` 做防御性解码与尺寸限制，最终渲染为 bounded 文本。

依赖方向单向向外：两个工具都只消费 `@deepseek-ai/dsh-workflow`、`@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-subagent`、`@deepseek-ai/cordis` 等运行时能力，不反向依赖彼此；tool-ralph 额外依赖 `dsh-subagent` 以校验 provider 能力。每个包独立维护 `package.json`、`tsconfig.json`、`README.*` 与 `tests/`，对外仅暴露 `.`、`./invariant`、`./types`（tool-workflow）三个入口。
