- 对不可信持久化数据采用“严格白名单解码”模式：用 `hasExactKeys` 校验字段集合后再构造冻结对象，任何缺失或多余字段均抛 `ScheduleLogError`。
- 输入错误与日志损坏错误分离：用户侧参数非法抛带稳定 `code` 的 `ScheduleInputError`，持久化流损坏抛 `ScheduleLogError`，工具层再映射为统一的 `ScheduleToolError` 输出。
- 所有写路径遵循“preflush → append → postflush”三段式，并使用 `runScheduleTransaction` 保证同一 Agent 的并发安全。
- 定时器延迟一律通过 `Math.min(target - now, MAX_TIMER_DELAY_MS)` 截断，避免 Node.js 最大超时值被静默截断导致死循环。
- 运行时状态机通过布尔标志（`stopping`/`requested`/`faulted`）+ Promise 哨兵（`stop`/`idleWait`/`run`）组合，确保 dispose 后不再调度且可幂等清理。
- 面向模型的提示文本通过 `renderReminderFraming` / `renderEveryReminderBatchFraming` 生成，动态字段一律 JSON 转义，禁止拼接原始 prompt。
