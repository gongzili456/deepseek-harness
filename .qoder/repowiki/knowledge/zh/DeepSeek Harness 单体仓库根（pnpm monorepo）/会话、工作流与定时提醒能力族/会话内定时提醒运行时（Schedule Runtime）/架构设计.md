模块以 Cordis 插件形式暴露 `apply(ctx)`，监听 `agent/created` 为每个新根 Agent 创建独立的 `ScheduleRuntime` 实例，并在其生命周期内注册 `schedule_create/list/delete` 三个工具。

内部按职责分层：
- `domain.ts`：纯函数层，定义 v1 协议（`SCHEDULE_CHANGE_VERSION`）、三种记录类型（after/at/every）、严格解码器（`decodeScheduleChange`、`foldScheduleEvents`）、时间解析（IANA zone、本地日历→UTC）、以及模型可见的提示渲染（`renderReminderFraming` / `renderEveryReminderBatchFraming`），对外抛出 `ScheduleLogError` 与 `ScheduleInputError`。
- `persistence.ts`：封装共享 session 持久化屏障 `ctx.sessions.flush`，将底层失败统一包装为 `SchedulePersistenceError`。
- `transaction.ts`：通过 `WeakMap<Agent, Promise>` 实现每 Agent 串行化的 `runScheduleTransaction`，保证读-折叠-追加-再 flush 的原子性。
- `runtime.ts`：进程内可销毁的定时器投影类，维护 `start/requestDrive/dispose` 状态机，使用 `dueDecision` 在 due 的一次性任务、固定速率批次与 wait 之间决策，借助 `setTimeout`（受 `MAX_TIMER_DELAY_MS` 限制）和 `agent.whenIdle()` 等待空闲，通过 `agent.runMaintenance` 投递 followup 并追加 `schedule/change` 事件。
- `tools.ts`：基于 `@deepseek-ai/dsh-tools` 的 `defineTool` 注册三个工具，所有写操作都先 preflight flush、再 append、再二次 flush，并以 `runCancellableScheduleTransaction` 保证取消语义。
- `index.ts`：插件入口，声明依赖服务 `['agents','sessions','tools','sessionPersistence']`，导出 domain 类型与工厂函数。

依赖方向单向：`tools → runtime → (domain + persistence + transaction)`，`runtime` 不反向依赖 tools；domain 完全无副作用，仅消费 `SessionEvent`。
