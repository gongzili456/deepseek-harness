- 后端类继承自 `SessionPersistence` 并实现 `PersistenceBackend<T>` 泛型参数（JSONL 用 `JsonlTornMarker`，SQLite 用 `number` seq），将具体存储细节与协调器解耦。
- 配置对象通过 `static Config = z.object({...})` 以 Schemastery schema 声明，并在构造函数中以 `config.x ?? DEFAULT_*` 形式兼容未走 schema 的程序化构造。
- 所有异步 I/O 方法接受可选的 `AbortSignal` 参数，并在关键步骤调用 `signal?.throwIfAborted()` 以支持取消。
- 文件/数据库访问错误统一通过 `isENOENT` 判断 ENOENT 语义，非 ENOENT 的错误直接上抛而非吞掉。
- revision 通过统一的工厂函数（`fileRevision` / `sqliteRevision`）生成带来源标识的字符串，使跨后端比较具备单调性与唯一性。
- 平台差异通过运行时分支（如 `process.platform === 'win32'`）分发到独立的 `*Win32` 辅助函数，POSIX 路径保持纯 Node fs 调用。
