本模块包含两个并列的 npm 包，分别实现 `@deepseek-ai/dsh-session-persistence` 中定义的 `PersistenceBackend` 接口，由上层 `PersistenceCoordinator` 统一编排生命周期、批写合并、冷启动准备与崩溃恢复。

- `session-persistence-jsonl`：以每个会话一个追加型文件（`session.jsonl` 或 `session.jsonl.zstd`）作为物理介质，按 `root → projectDir(cwd) → encodeSegment(id)` 目录组织；`index.ts` 中的 `JsonlSessionPersistence` 类负责编码/解码、Zstandard 帧扫描、POSIX 下 link+fsync 原子发布、Win32 下专用 durable publish、torn-tail 修复以及只读路径上的 revision 稳定读取（stat→read→stat 循环）。`format.ts` 定义 JSONL 行格式与 header/meta 编解码，`zstd*.ts` 封装原生 `koffi` 调用的 zstd 编解码器（含独立可解码的首帧校验），`win32.ts` 提供 Windows 专属的目录 fsync 与原子发布。
- `session-persistence-sqlite`：将 session 元数据与事件映射为 `sessions` / `events` 两张表，`schema.ts` 声明表结构与版本、`rowToMeta`/`scanRows` 负责序列化与 torn 检测；`index.ts` 中的 `SqliteSessionPersistence` 使用 Node 内置 `node:sqlite` 的 `DatabaseSync`，所有写路径（appendBatch、commitRepair）包裹在单个事务内以保证原子性，revision 由 `storeIdentity:incarnation:revision` 构成。

依赖方向：两个后端都仅向上依赖 `@deepseek-ai/dsh-session-persistence`（抽象基类与协调器）、`@deepseek-ai/dsh-session`（类型）、`@deepseek-ai/cordis`（Context 注入），彼此之间无耦合，可独立安装与替换。
