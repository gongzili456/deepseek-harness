本模块由四个相互协作但职责分离的独立 npm 包组成，围绕 `@deepseek-ai/dsh-session-projection` 和 `@deepseek-ai/cordis` 服务框架构建：
- `session-projection-cache`：通过 `SessionProjectionCache` Service 维护 `session_projcache` 域表，以 count/interval 双触发写回 + turn/end 与 session/disposed 两个强制落盘点实现 write-behind；冷读路径按 `cachedSnapshot → persistence.readFrom(floor) → restore(0)` 三级阶梯恢复，并以 `createdAt/cwd` 身份匹配防止跨生命周期污染。
- `session-stats`：纯函数式 `ProjectionDefinition<'sessionStats'>`，将 `step/start|end`、`assistant/chunk|message`、`tool/call|result` 折叠为 turns/steps/llmMs/toolMs/ttftMs/decodeMs 等总量，仅注册到 `ctx.sessionProjections`，不持有状态。
- `session-telemetry`：定义 `SessionTelemetryBackend` 抽象类、`SessionTelemetrySink` 接口、`SessionTelemetryRecord` 逻辑记录模型与 `SessionTelemetryCoordinator` 捕获协调器；协调器订阅 `session/event`、`agent/error` 等总线，执行固定 chunk 投影（每 turn:step 仅首块）、`session-telemetry/record` 瀑布红改、severity 预映射，并通过 `handoffCursor` WeakMap 在 HMR 重接入时避免重复投递。
- `session-telemetry-otel`：基于 `@opentelemetry/sdk-logs` + `OTLPLogExporter` 实现 `OpenTelemetrySessionBackend`，通过 `mode`（FULL / FEEDBACK_ONLY / DISABLED）选择 live 或 on-demand 捕获模式，将 SDK 配置透传并自带 provider shutdown 超时边界。
依赖方向单向：telemetry-otel → telemetry → (session, agent, cordis)；stats 与 cache 均只消费 projection 与 session 能力，彼此无耦合。
