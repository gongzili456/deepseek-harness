本模块由三个相互协作的子域组成，均遵循 `@deepseek-ai/cordis` 插件模式：

- `packages/storage/`：分层 KV 存储。
  - `storage-domain` 定义领域模型（`DomainSpec`、`KvTable`、`DomainGlobal`）与单写链语义，维护权威内存快照并在每次持久化成功后发出 `domain/changed` 事件；读操作完全同步自内存，写操作串行化到一条 Promise 链上，保证内存与介质一致。
  - `storage` 作为 Hub，暴露 `StorageBackendRegistry` 和 `Storage.mount/form` 表单挂载机制，将领域层以 `ctx.storage.domain` 形式装配到上下文。
  - `storage-json` 与 `storage-sqlite` 是具体后端实现，各自导出 `apply(ctx, config)` 插件函数，在 `inject = ['storage']` 后调用 `ctx.storage.backend.register('json'|'sqlite', backend)` 注册，并通过 `storageBackendServiceKey(name)` 暴露原始后端供高级消费者使用；两者共享 `UNIT_NAME_RE` 命名约束与 `version-mismatch` 版本校验。
  - 依赖方向严格单向：`storage-json/sqlite` → `storage` → `storage-domain`，领域层不感知任何介质。

- `packages/spill/`：大文本溢出存储。
  - `spill` 仅定义抽象 `SpillStore` 服务（`saveText`），扩展 `Context.spillStore`，不持有策略或检索 API。
  - `spill-local` 提供基于 OS tmpdir 的本地实现，按 session hash 隔离目录，文件名用 `encodeSegment` 做路径安全编码并以随机前缀防碰撞，写入采用 `wx + 0o600` 独占锁。
  - `spill-policy` 定义溢出策略类型，与 `output-retention` 解耦。

- `packages/compaction/`：对话历史压缩。
  - `compaction` 定义抽象 `CompactionEngine`（`compactIfNeeded` / `compactNow` / `compactRegion`），并暴露 `ManualCompactionError`、`toolPairingBalanced*`、`compactCheckpointSource` 等跨包契约；`checkpoint.ts` 被刻意保持 cordis-free 以便客户端与 wire 程序引用。
  - `compaction-basic` 是默认实现，监听 `agent/pre-step`、`agent/request-error`（CONTEXT_WINDOW_EXCEEDED_CODE）自动触发压力/溢出压缩，通过 `ctx.tokenMeter` 测量 token 用量并按 `modelPolicies` 选择阈值，调用 `summarizeWithLlm` 生成摘要。
  - `compaction-tool-result-pruner` 提供可选的工具结果裁剪服务，通过 `ctx.get('toolResultPruner')` 动态发现。
  - `command-compact` 是 `/compact` 命令适配器，将 `ManualCompactionError.code` 映射为用户可读的 `CommandResult`。
  - 依赖方向：`compaction-basic` / `command-compact` → `compaction`，且 `compaction-basic` 可组合 `compaction-tool-result-pruner`。

整体依赖方向自上而下为：命令/策略 → 抽象服务 → 具体实现，所有跨进程通信通过 Cordis 的 `Context` 注入与事件总线完成，无全局单例。
