- 每个子包通过导出 `name`、`inject`、`Config` schema 与 `apply(ctx, config)` 插件函数来注册到 Cordis，后端实现再额外调用 `ctx.storage.backend.register` 注册命名后端。
- 抽象服务类继承 `Service` 并在构造函数中调用 `super(ctx, '<service-name>')`，同时通过 `declare module '@deepseek-ai/cordis'` 合并 `Context` 接口暴露 `ctx.<service>`。
- 所有对外错误使用具名 `Error` 子类（如 `StorageError`、`DomainError`、`ManualCompactionError`）并携带稳定 `code`，便于上层按语义分类处理而非匹配消息字符串。
- 后端实现通过 `UNIT_NAME_RE` 对 unit/table 名称做正则校验，拒绝非法标识符后再构造文件或 SQL 语句，确保名称可直接用作文件名与 SQL 标识符段。
- 写路径统一采用“先持久化、再改内存、最后发事件”的顺序：`DomainImpl` 的 write chain 在 `unit.putRecord` 解析后才更新内存并 emit `domain/changed`，失败时回滚内存。
- 资源释放使用 idempotent close：后端与 domain 的 `close()` 内部缓存 `Promise<void>` 守卫重复调用，并发关闭等待同一 teardown 完成。
