本模块由两个相互独立的 Cordis 子包组成：
- `llm-retry`（`@deepseek-ai/dsh-llm-retry`）：以插件形式暴露 `apply(ctx, config)` 入口，通过 `ctx.on('agent/request-error', ...)` 拦截下游请求失败，依据每个 Provider 配置的 `ResolvedRetryPolicy`（`normal`/`always` 两种模式、指数退避 + jitter、`providerRetryAfterMs` 优先）计算重试延迟；使用 `AbortController` 组合 session 信号与插件生命周期信号实现可取消等待，并通过 `agent.session.append('llm/retry'|'llm/retry-started')` 写入持久化事件；通过类型声明扩展 `dsh-session/types` 的 `SessionEventMap` 注册新事件。
- `token-meter`（`@deepseek-ai/dsh-token-meter`）：以 `TokenMeter extends Service` 形式挂载到 `ctx.tokenMeter`，监听 `session/event` 并维护 per-session 的 `ReplayState`（`consumedEvents`、`header`、`surface`、`surfaceTokens`、`stepStart`、`anchor`），在 `_sync` 中顺序重放会话日志，用 `_foldEvent` 处理 `request/header`、`step/start`、`step/end`、`assistant/message` 等事件；通过 `estimate.ts` 中的固定密度启发式（CHARS_PER_TOKEN=4、BLOCK_OVERHEAD、ROLE_OVERHEAD）对 header、content、工具 schema 进行无状态 Token 估算；借助 `surface-fold.ts` 维护当前 surface 节点树并按增量计算 `surfaceDeltaTokens`；可选注入 `sessionProjections` 注册 token usage / context pressure / context breakdown 三类投影定义，使外部消费方可以查询压力与拆解。
依赖方向：两者均只向上依赖 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-llm`，不反向依赖上层业务；`llm-retry` 通过事件总线解耦于具体 Provider，`token-meter` 通过纯函数 `estimate.*` 与 `BlockAssembler` 保持估算逻辑可测试且与回放状态隔离。
