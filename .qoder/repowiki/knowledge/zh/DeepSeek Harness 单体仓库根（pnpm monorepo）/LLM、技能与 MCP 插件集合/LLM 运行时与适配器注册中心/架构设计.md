模块以 `LlmRuntime`（继承自 `@deepseek-ai/cordis` 的 `Service`）为核心，维护三个内部映射：`adapters`（provider→适配器注册）、`directory`（可配置 provider 目录）和 `discoveries`（按 settingsNs 注册的模型发现回调）。对外通过 `registerAdapter` / `registerConfigurableProviders` / `registerModelDiscovery` 进行原子替换式注册，返回带 `replace()` 句柄的可处置资源；所有变更在同步区间内完成并通过 `llm/adapters-updated` 事件广播。

请求入口为 `stream(options)`，内部经 `ctx.waterfall('llm/stream', ...)` 暴露给插件/循环做重试、重放、路由等拦截；最终由私有 `adapterStream` 选择适配器并迭代其 `AsyncIterable<StreamChunk>`，将适配器抛错统一转为终端 `finish { reason: 'error'|'aborted' }` chunk。

能力解析层 `prepareCall`/`resolveCallConfig`/`resolveModelInfo` 先查询 adapter 的 exact-model 元数据，校验并冻结后生成只读的 `PreparedLlmCall`，确保一次准备只能分发一次且后续 config 不得漂移。

辅助子模块职责清晰：`types.ts` 定义 provider 中立的消息、内容块、流协议与失败事实；`message.ts` 构造不可变消息；`assembler.ts` 的 `BlockAssembler` 把流式 delta 增量拼装为完整 `ContentBlock` 与 assistant 消息；`retry-policy.ts` 用 schemastery 校验并固化 normal/always 两种指数退避+抖动策略；`call-config.ts` 提供字段级相等比较与 deep-freeze（跳过 AbortSignal）；`api-key.ts`、`adapter-failure.ts`、`error.ts`、`brand.ts`、`invariant.ts`、`never.ts` 提供认证、错误归一化、类型品牌与断言工具。依赖方向单向：运行时 → 各工具模块 → 外部 cordis/schemastery/dsh-* 包，适配器仅实现 `LlmAdapter.stream` 抽象类。
