模块以 Cordis 插件形式暴露 `apply(ctx, config)` 作为入口（`src/index.ts`），按 `transport` 字段区分 stdio 与 streamable-http 两种配置；`src/transport.ts` 根据配置创建对应的 MCP SDK Transport（StdioClientTransport 或 StreamableHTTPClientTransport），并对子进程环境调用 `scrubbedParentEnv()` 做凭据清洗。

核心由 `src/connection.ts` 的 `startConnection` 实现：维护一个带代际（generation）的 MCP Client，监听 `tools/list_changed` 通知并串行化同步（`syncChain` Promise 链），在断开时按指数退避 + 最大尝试次数策略重连，耗尽后注销该服务器的全部工具；`ready` Promise 用于插件激活前等待首次连接/发现完成，配合 `failOnStartupError` 决定是否拒绝 fiber。

`src/tools.ts` 负责工具桥接：通过分页 `tools/list` 拉取定义，用 `publicToolName(serverName, rawName)` 生成满足 DeepSeek 函数名约束（≤64 字符、仅 `[A-Za-z-]`）且带 12 位 SHA-256 后缀的稳定公共名；两阶段同步（先 fetch 构建新代际，再 swap 替换旧 disposers）保证原子切换，注册冲突会回滚整代并记录日志；每个工具的 execute 闭包使用原始 MCP 名称发起 `tools/call`，支持 abort signal 与超时，并将结果映射为 `{content, structuredContent?}` 的规范结构。

依赖方向单向：`index → connection → {transport, tools}`，类型通过 `@deepseek-ai/dsh-tools` 的 side-effect type import 将 `ctx.tools` 合并到 Context；测试位于 `tests/`，包含 e2e、reconnect、fixture server 等用例。
