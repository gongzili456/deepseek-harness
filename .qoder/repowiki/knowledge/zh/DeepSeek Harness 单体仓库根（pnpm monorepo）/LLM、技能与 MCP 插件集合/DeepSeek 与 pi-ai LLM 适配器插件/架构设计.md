本模块包含两个并列的 Cordis 插件包，均实现 `@deepseek-ai/dsh-llm` 暴露的 `LlmAdapter` 接口并通过 `ctx.llm.registerAdapter` 注册到统一的 LLM 路由表。

- `llm-deepseek`（`@deepseek-ai/dsh-llm-deepseek`）：单提供者插件，固定注册 `deepseek-official` 路由。`src/index.ts` 通过 `installSettingsSection('llm-deepseek', ...)` 挂载用户设置，`resolveAdapterOptions` 将配置、`launchEnvironmentOf` 中的 `DEEPSEEK_BASE_URL` 和 `credentialRef` 合并为不可变 `ResolvedDeepSeekOptions`；`adapter.ts` 中的 `DeepSeekAdapter` 仅负责 HTTP + SSE 流式调用、SSE 解析（`sse.ts`）、请求序列化（`serialize.ts`）与错误码映射（`translate.ts`），连接事实通过每操作调用的 thunk 读取以支持热更新。
- `llm-pi-ai`（`@deepseek-ai/dsh-llm-pi-ai`）：多提供者通用插件，描述为 design-verification twin。`config.ts` 用 Schemastery 校验每个 provider route 的 profile，`provider.ts` 基于 URL/协议构建 pi-ai `Provider`，`catalog.ts` 维护已安装 provider 清单，`discovery.ts` 暴露模型发现能力。`adapter.ts` 的 `PiAiAdapter` 每次操作构造不可变 `PiAiSnapshot`（profiles + Models 集合），保证在流式消费期间配置变更不会污染已在进行中的请求。`index.ts` 同时维护可配置 provider 目录（`registerConfigurableProviders`）与路由注册（`registerAdapter`），并通过 `deepEqualJson` 比较快照做原子 `replace`，避免路由抖动。

依赖方向单向指向共享基础设施：`dsh-llm`（适配器基类、重试策略）、`dsh-settings`（设置段）、`dsh-credentials`（密钥引用）、`dsh-launch-environment`（受信任环境变量）、`dsh-timeout`（空闲超时）、`dsh-invariants`、`dsh-anonymous-user-id`；`llm-pi-ai` 额外依赖 `@earendil-works/pi-ai` 作为底层 SDK。两个包均通过 `exports` 字段暴露根入口与 `./invariant` 子路径。
