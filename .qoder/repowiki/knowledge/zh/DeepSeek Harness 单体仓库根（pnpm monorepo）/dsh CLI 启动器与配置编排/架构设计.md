模块以 `src/bin.ts` 为 Node 入口（package.json `bin.dsh` → `lib/bin.js`），通过 Commander 在 `src/args.ts` 中解析三类调用：`profile`、`plugin`、`dump-config`；`bin.ts` 根据 mode 使用 `await import()` 按需加载对应处理器，避免无关代码进入 dispatch 路径。
- `profile-boot.ts`：核心编排层，负责 `prepareProfile`→`composeProfile`→`boot` 的完整生命周期，按顺序叠加 bundle 层、profile 自身 patch、`$DSH_HOME/cordis.patch.yml`、`--patch` 覆盖层与 DSH_TELEMETRY_DISABLED 开关，并通过 `watchUserPatches` 实现用户补丁热重载；同时注入 `DSH_LAUNCH_ENVIRONMENT_KEY` 与命令行快照到上下文，并安装 SIGTERM/SIGINT 有界关闭。
- `plugin.ts`：`dsh plugin` 子命令，作为 pnpm 转发器，在 profile 目录执行 pnpm 并在成功后基于已安装包清单自动 reconcile `dsh.profile.bundles` 列表。
- `dump-config.ts`：纯配置渲染入口，复用 include 插件的 patch 算法输出分层注释化的配置树，不启动任何应用。
- `process-shutdown.ts`：统一的进程退出控制器，供 profile 与 dump 模式协调资源释放。
- `config/agent-presets/`：随包分发的 agent preset 根目录，由 `runProfile` 在 composition 中追加为只读 system trust 根。
构建侧通过 `tsdown.config.ts` 将 `lib/types/bin.js` 打包为单一 ESM 可执行文件，声明文件由顶层 `tsc -b` 生成。
