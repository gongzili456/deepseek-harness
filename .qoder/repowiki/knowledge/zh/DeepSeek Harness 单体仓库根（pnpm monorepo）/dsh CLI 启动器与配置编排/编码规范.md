- CLI 入口通过 `switch (invocation.mode)` 配合 `await import('./xxx.ts')` 按需加载处理器，避免未用模式被引入。
- 参数解析统一集中在 `args.ts`，使用 Commander 的 `allowUnknownOption` + `passThroughOptions` + `enablePositionalOptions` 将未知 token 透传给被启动的应用。
- 每个处理器文件导出独立的 `runXxx` 函数并由 `bin.ts` 调用，便于测试直接驱动而不经过进程边界。
- 配置文件分层遵循固定顺序：bundle 层 → profile 自身 patch → `$DSH_HOME/cordis.patch.yml` → `--patch` 覆盖层 → 环境开关，且每层通过 `loadOptionalPatches`/`loadOverlayPatches` 读取。
- 对可变的 patch 对象在每次 recomposition 时使用 `structuredClone` 深拷贝，防止 include 插件的 insert 引用在不同轮次间互相污染。
- 进程信号处理统一通过 `createProcessShutdown` 提供的 shutdown controller 协调，SIGTERM 退出码 0、SIGINT 退出码 130。
