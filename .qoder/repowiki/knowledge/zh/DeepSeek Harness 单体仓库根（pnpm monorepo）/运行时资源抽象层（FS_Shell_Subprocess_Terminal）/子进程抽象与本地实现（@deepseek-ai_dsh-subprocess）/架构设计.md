模块由两个并列的 npm 包组成，通过 Cordis Service 插件机制解耦：
- `subprocess/`（`@deepseek-ai/dsh-subprocess`）仅暴露纯类型与抽象类 `SubprocessRuntime`（继承自 `@deepseek-ai/cordis` 的 `Service`），在 `src/index.ts` 中通过 `declare module '@deepseek-ai/cordis'` 将 `ctx.subprocess` 挂载到上下文；`types.ts` 集中定义 `SubprocessSpawnSpec`、`SubprocessHandle`、`SubprocessTerminalHandle`、`CollectedOutput` 等契约，并导出 `scrubbedParentEnv()` 与 `SENSITIVE_ENV_PATTERN` 作为跨实现的共享环境清洗规则。
- `subprocess-local/`（`@deepseek-ai/dsh-subprocess-local`）实现 `LocalSubprocessRuntime extends SubprocessRuntime`，依赖 `node:child_process` 完成普通子进程树（`spawn.ts`）、`node-pty` 完成终端会话（`terminal.ts`），并通过 `process-inspector.ts` 封装 Linux `/proc` 前缀探测以支持前台进程组信号投递。
- 依赖方向单向：`subprocess-local` → `subprocess` 的类型与服务基类，`subprocess` 不感知任何平台细节；每个 spawn 返回的 handle 被服务实例的 `live` / `terminals` Set 持有，以便在 Cordis effect 钩子（`process.exit` 监听）中做同步强制终止。
- 输出收集采用“内存尾 + 可选 spill 文件”双缓冲策略（`OutputCollector`），溢出时写入私有 tmpdir 下的随机命名日志文件，保证诊断可恢复且路径不可预测。
- 终止语义统一为 SIGTERM→graceMs→SIGKILL 升级，POSIX 使用进程组、Windows 使用 `taskkill /T`，并在 host exit 阶段提供无等待的 `terminateForHostExit` 兜底。
