四个子包遵循同一分层模式：每个能力均拆分为 `*-service`（定义 `ctx.xxx` 接口与类型）、`*-local`（基于 Node 原生 API 的默认实现）、`*-sandbox`（通过 bwrap/landlock/seatbelt 等机制隔离的实现），以及 `tool-*`（将能力包装为模型可调用的工具）。跨子模块的协作关系如下：
- `subprocess` 是底层基石，被 `terminal`（PTY 会话）和 `shell`（bash/pwsh 执行器）共同依赖，用于受控的子进程树管理与输出收集。
- `fs` 的沙箱实现与 `shell` 的沙箱执行器共享相同的隔离策略（bwrap/landlock），使文件访问与命令执行处于同等安全边界内。
- `terminal` 的 Bash 后端复用 `shell` 的 bash 执行器，形成「终端 → Shell 执行器 → 子进程」的调用链。
- 所有子包通过统一的 `invariant.ts` 校验入口参数，并通过 `package.json` 中的 `exports` 仅暴露稳定服务接口，隐藏内部实现细节。
