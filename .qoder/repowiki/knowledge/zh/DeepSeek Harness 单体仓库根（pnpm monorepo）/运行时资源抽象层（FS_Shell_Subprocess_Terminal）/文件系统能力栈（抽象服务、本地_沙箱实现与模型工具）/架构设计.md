模块按职责拆分为多个独立 npm 包，围绕 `@deepseek-ai/dsh-fs` 定义的 `FileSystem` 抽象类形成清晰的依赖方向：
- `fs/`：纯接口层，定义 `FsTarget`/`FsVersion`/`FsWriteIntent`/`FsEditRequest`/`FsError` 等词汇类型，并通过扩展 `@deepseek-ai/cordis` 的 `Context` 与 `Events` 声明 `fs/write-intent`、`fs/edit-intent`、`fs/observed` 三个事件门；不依赖任何具体后端。
- `fs-local/`：基于 Node `fs` 的本地实现 `LocalFileSystem`，通过 realpath 派生稳定 `targetKey`，使用 per-targetKey 的尾 Promise 队列串行化写/编辑临界区，并以原子写入完成 `writeText`/`editText`。
- `fs-sandbox/`：继承 `LocalFileSystem`，仅重写 `writeText`/`editText`，在调用前根据 `SandboxExecutionPolicy`（read-only / workspace-write / danger-full-access）对目标路径做 containment 检查，拒绝时抛出 `FS_SANDBOX_DENIED`。
- `fs-observation-policy/`：无服务的 Cordis 插件，注册三个 `fs/*` 监听器，用 `WeakMap<owner, Map<targetKey, FsObservation>>` 维护每会话观测状态，将读到的存在/缺失转化为 `createIfAbsent` 或 `replaceIfVersion` 意图，使 edit 必须先 read。
- `tool-fs/`：模型侧工具入口，注册 `read`/`write`/`edit`/`read_image` 到 `ctx.tools`，负责读窗口限制、行/字节截断、沙箱升级字段广告（读取 `ctx.fs.sandboxMode`），并消费 `fs/*` 事件门。
- `tool-fs-search/`：独立于 provider 的搜索工具，直接通过 `ctx.subprocess` 启动打包的 `@vscode/ripgrep` 二进制执行 glob/grep，结果由后续 `read` 工具消费。
- `tool-str-replace-editor/`：字符串替换编辑器工具。
依赖方向单向：tool-* → fs（抽象）→ 可选 policy/sandbox；search 不依赖 provider 抽象，避免把搜索纳入文件系统契约。
