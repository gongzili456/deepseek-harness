模块由两部分组成：
- 应用入口：`index.html` 挂载 `src/main.ts`，仅调用 `@deepseek-ai/dsh-client-web` 的 `AppWebEntry` 完成渲染；所有业务逻辑、插件装配、模块表填充均位于被引用的 shell 库中。
- 构建配置：`vite.config.ts` 通过自定义插件拒绝独立 serve（强制走 `dsh web`），将 `katex/shiki/mdast-*` 等重型依赖拆入 `vendor` chunk，按包名把 `@shikijs/langs` 语法文件归入 `assets/langs/`，字体归入 `assets/fonts/`；通过 `resolve.alias` 把 `@deepseek-ai/dsh-client-web*` 等 workspace 包直接指向源码以走 CSS 管线，并用 `define` 注入 `process.versions.node='0.0.0'` 使 vendored cordis loader 走浏览器分支。
- 测试层：`tests/` 下每个 `.e2e.ts` 对应一个场景，使用 `tests/scaffold.ts` 提供的 `launchWebScaffold` 在进程内组装 Cordis 树（加载 `packages/bundle/base/cordis.patch.yml` 与 `web-app/cordis.patch.yml`，再叠加 `*.overlay.yml`），启动真实 webserver 并由 Playwright 驱动 Chromium；`tests/assembled-boot.ts` 提供 jsdom 下的最小化 AppWebEntry 挂载用于快照测试。模式由 `$DSH_SNAPSHOT` 控制：replay（默认，回放 fixture）、record（真实 LLM 录制）、refresh（重写 golden）。fixture 为 `session.jsonl`，golden 为 `ui.expected.md` / `geometry.expected.md` 等文本快照，经 `normalizeAria` 与 `stabilizeFixtureMessageIds` 去稳态后比对。
