模块以 `@deepseek-ai/dsh-plan-mode` 包形式发布（见 `package.json`），核心由 Cordis `Service` 实现：
- `src/index.ts` 导出 `PlanModeController`，在构造时注册三类扩展点：① `agent/pre-step` 钩子，在每次被接受的 in-turn pre-step 边界追加 `plan/mode` 事件并注入提示；② `systemPrompt.section('plan:policy')`，按当前 plan mode 是否激活动态插入部署方提供的 guidance；③ `tools.register(defineTool(...))` 注册稳定的 `exit_plan_mode` 工具，调用 `userQuestions.ask` 发起 Approve / Keep planning 的用户评审。
- 状态通过 `session-projection` RFC 以纯双事件折叠维护：`command/run(name='plan')` 记录用户选择，`plan/mode` 提交最终值并清空 pending，视图输出 `{active, pending}`。
- 类型与客户端契约解耦：`src/types.ts` 是单一来源的 `PlanProjection` 接口与 `SessionProjectionMap` 声明，`src/client.ts` 仅 re-export 该类型供客户端消费，避免重复。
- `src/invariant.ts` 作为独立的 companion plugin（`apply` 导出）向 `@deepseek-ai/dsh-invariants` 注册校验器，对 `plan/mode` 事件的 `active` 字段做布尔约束，并在 seed 阶段扫描已有 session 日志。
- 依赖方向单向向外：仅依赖 `@deepseek-ai/cordis`、`dsh-session`、`dsh-tools`、`dsh-system-prompt`、`dsh-user-questions`、`dsh-session-projection`、`dsh-invariants` 等 peer 包，自身不持有运行时状态之外的副作用。
