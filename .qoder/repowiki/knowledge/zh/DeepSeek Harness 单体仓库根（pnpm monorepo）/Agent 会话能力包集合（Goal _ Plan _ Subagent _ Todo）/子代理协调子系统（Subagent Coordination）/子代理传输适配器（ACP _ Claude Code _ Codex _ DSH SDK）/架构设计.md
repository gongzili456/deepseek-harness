本模块由四个并列的 npm 包组成，每个包对应一种子代理后端，遵循相同的分层结构：
- `src/index.ts` 暴露 `name`、`inject`、`Config` schema（基于 `@deepseek-ai/schemastery`）、`SubagentProvider` 实现类以及 `apply(ctx, config)` 注册函数，通过 `ctx.subagents.registerProvider` 挂载到 Cordis。
- `src/run.ts`（或 `run.ts` + `wire.ts`/`process.ts`）实现具体后端的启动、协议握手、请求转发、结果折叠与终止阶梯（EOF 宽限 → SIGTERM → SIGKILL），并通过 `@deepseek-ai/dsh-subagent` 提供的 `settleRunResult`、`subprocessRunHandle`、`AssistantOutputFold` 等共享原语统一行为。
- 依赖方向单向向外：仅依赖 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-subagent`、`@deepseek-ai/dsh-subprocess`、`@deepseek-ai/dsh-session` 及各后端官方 SDK；不反向引用其他三个适配器包。
- 进程模型分两类：ACP 与 DSH SDK 直接通过 `ctx.subprocess.spawn` 或 `dsh-sdk-client` 的 `DeepSeekHarness` 管理子进程；Claude Code 通过 `process.ts` 中的 `ManagedClaudeCodeProcess` 把共享子进程句柄投影为 Anthropic Agent SDK 的 `SpawnedProcess`；Codex 通过 `wire.ts` 的 `CodexAppServerWire` 在 `JsonRpcLineTransport` 上实现 app-server 0.147.0 协议。
- 所有适配器均声明 `NO_START_CAPABILITIES`（`outputSchema`/`depthLimit`/`toolFilter`/`persona` 全关）且 `inheritsParentContext = false`，因为子进程无法继承父会话上下文。
- 工作目录解析统一从 `request.parent.session.header.cwd` 派生，或通过配置覆盖并经 `validateConfiguredCwd`/`resolveChildCwd` 校验绝对可访问路径。
- 测试位于各包 `tests/` 下，包含 `loader-composition.e2e.ts` 验证插件加载组合，以及针对真实/模拟后端的 spec/e2e 用例。
