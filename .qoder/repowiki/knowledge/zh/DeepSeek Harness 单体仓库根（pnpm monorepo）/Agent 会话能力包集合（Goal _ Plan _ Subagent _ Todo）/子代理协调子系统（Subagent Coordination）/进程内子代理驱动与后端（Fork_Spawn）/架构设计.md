模块由三个独立 npm 包构成，依赖方向单向：`subagent-fork-in-process` 与 `subagent-spawn-in-process` 作为 `SubagentProvider` 插件注册到 `ctx.subagents`，二者共同复用 `subagent-in-process-driver` 提供的 `startInProcessRun` 来创建、驱动并回收子 Agent。
- `subagent-in-process-driver`（核心）：在 `setup` 回调中注入委托策略覆盖、应用子代理组合（persona/toolFilter）、可选挂载结构化输出运行时（`structured.ts`），通过 `parent.ctx.agents.create` 创建子 Agent，随后调用 `followup` 发送提示并等待 `whenIdle`，最终从子会话事件切片读取结果；负责将 `TurnEndReason` 映射为 `SubagentStopReason`、处理 AbortSignal 取消与资源释放。
- `structured.ts`：以 child 作用域工具 `structured_output` + 系统提示段（order 190）+ tools.guard 三重机制实现两阶段提交——先暂存执行参数，再监听 `tools/result` 权威通知后提交，并通过 WeakMap 隔离并发 run 的状态。
- `subagent-fork-in-process`：`inheritsParentContext = true`，通过截取父会话最后一个 `turn/end` 之前的 `SessionEvent[]` 作为 seed 传给 driver，使子代理继承对话上下文；同时暴露 `prepareContinuable` 固定该 seed 用于冷启动恢复。
- `subagent-spawn-in-process`：`inheritsParentContext = false`，不传 seed，子代理从零会话开始。
所有包均通过 `apply(ctx, config)` 导出插件入口，使用 `schemastery` 声明配置 schema，并以 `peerDependencies` 声明对 `@deepseek-ai/dsh-subagent`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-agent` 等运行时包的依赖。
