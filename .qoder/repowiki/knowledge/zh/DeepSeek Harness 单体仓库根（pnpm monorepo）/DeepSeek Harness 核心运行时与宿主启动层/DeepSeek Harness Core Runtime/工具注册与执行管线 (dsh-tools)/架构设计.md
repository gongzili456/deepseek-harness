模块以 `src/index.ts` 中的 `ToolRuntime`（继承自 `@deepseek-ai/cordis` 的 `Service`，注入 `systemPrompt`）为单一入口，通过 `ScopedLayers` + `ToolLayer` 实现按 scope 叠加的工具注册、限制（allow/deny）和守卫（guard），并维护一个全局保留的 `run_code` Code Mode 传输。

内部按职责拆分为多个文件：
- `schema.ts`：统一的参数/值 JSON Schema DSL（`defineTool`、`ValueSchemaSpec`、`ParameterSchemaSpec`）及其编译与类型推断；
- `json-schema.ts`：受支持的原始 JSON Schema 子集校验（`assertSupportedJsonSchema`、`validateJsonSchemaValue`）；
- `code-mode.ts`：`run_code` 传输的实现，负责 SDK 生成、子调用调度池、并发/独占屏障、结果大小限制与 spill；
- `ts-types.ts` / `py-types.ts`：将可见工具集合渲染为 TypeScript 或 Python SDK 文本，由 `SDK_RENDERERS` 表按 `ctx.codeRuntime.language` 分派；
- `presentation.ts`：工具拥有的 UI 呈现意图（`ToolCallView` / `ToolResultView` 的 card 词汇）；
- `types.ts` / `testing.ts` / `invariant.ts`：共享类型、测试夹具与不变式断言。

依赖方向单向向外：本包仅依赖 `@deepseek-ai/schemastery`（运行时），并通过 peer dependency 消费 `@deepseek-ai/dsh-scope`、`@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-code-runtime`、`@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-user-approval` 等 core 包，不反向被它们引用。`package.json` 通过 `exports` 暴露 `.`、`./invariant`、`./types`、`./presentation` 等子路径，使外部插件可按需引入最小 API。
