模块由两个协作的包组成，依赖方向单向：`@deepseek-ai/dsh-agent`（packages/core/agent）仅暴露接口与运行时基础设施，`@deepseek-ai/dsh-agent-loop`（packages/core/agent-loop）实现具体驱动。

- `dsh-agent` 核心：
  - `runtime-types.ts` 定义 `Agent`、`AgentOptions`、`AgentStatus`、`PreStepDecision`、`RequestErrorAction` 等公共类型及 Cordis 事件扩展；`types.ts` 补充 `InboxTarget` 等。
  - `index.ts` 中的 `AgentRegistry` 继承自 Cordis `Service`，维护 `Map<SessionId, AgentEntry>` 存储活跃 Agent，并通过 `AsyncLocalStorage` 维护 `currentInitiator()` / `withInitiator()` / `withoutInitiator()` 发起者作用域链，用于同进程因果归属。
  - 通过 `setFactory(AgentFactory)` 将创建/恢复委托给插件实现，避免在接口层耦合具体循环；`register`/`enter`+`announce` 分离插入与发布，保证 `agent/created` 与 `agent/disposed` 成对且可回滚。
  - `inbox.ts`、`consumed-work.ts`、`model-selection.ts`、`dispatch.ts` 提供消息入队、已消费工作追踪、模型选择策略以及带 scope 的事件分发。

- `dsh-agent-loop` 核心：
  - `index.ts` 中的 `AgentLoop` 实现 `AgentFactory`，是 Cordis 插件，注入 `agents/sessions/llm/tools/systemPrompt`，在构造时安装设置项 `AGENT_LOOP_SETTINGS_NAMESPACE`、注册系统提示变量（provider/model/cwd），并遍历 `config.agents` 在启动期创建或恢复。
  - `prepare()` 构造 `ReactLoopAgent`，组合 caller 取消信号、工厂卸载信号与 owner fiber 卸载为单一 `AbortController`，返回 `PreparedAgent.publish()` 原子完成 session/agent 注册与 `agent/session-start` 事件。
  - `FactoryOwnership` 集中跟踪所有活跃 agent 的 dispose 与配置启动任务，在卸载时统一中止并等待收敛。
  - `agent.ts` 中 `ReactLoopAgent` 用有限状态机（idle/maintenance/running）驱动单条 Session，按 turn/step 边界消费 `Inbox`，组装 system prompt 后调用 LLM，再通过 `tool-calls.ts` 执行工具调用。
  - `runtime-context.ts`、`constants.ts`、`invariant.ts` 提供运行时上下文投影、默认并行度常量与断言。

依赖方向严格：loop → agent（实现接口），agent 不反向依赖 loop；两者均依赖 `@deepseek-ai/cordis` 作为服务容器与效果生命周期框架，依赖 `@deepseek-ai/dsh-session` 提供 Session/SessionId 等持久化边界。
