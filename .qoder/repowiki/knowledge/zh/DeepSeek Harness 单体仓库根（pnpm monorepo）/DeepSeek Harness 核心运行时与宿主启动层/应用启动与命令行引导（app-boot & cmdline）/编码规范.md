- 通过扩展 `@deepseek-ai/cordis` 的 `Context` 模块声明（`declare module '@deepseek-ai/cordis' { interface Context { ... } }`）向插件树注入宿主能力（如 `dshHomePath`、`cmdlineArgs`、`appExit`），而非直接修改类型文件。
- 所有对外 API 接受 `binName: string` 作为诊断前缀，错误消息统一以 `${binName}: <detail>` 形式输出，便于多二进制复用同一启动逻辑时区分来源。
- 对可选资源（`.env`、用户补丁文件）采用「读取 → 校验 → 批量应用」三段式：先解析全部层再合并，任何一层的 bootstrap-only 变量立即抛错，避免部分生效的中间状态。
- 对 Loader 失败的兜底统一通过 `installFailLoud` 注册 `unhandledRejection` 处理器，在释放钩子超时（`FAIL_LOUD_RELEASE_TIMEOUT_MS = 2000`）后强制 `exit(1)`，保证终端状态被恢复后再退出。
- 配置文件与补丁文件解析均复用 `cordis-plugin-include` 提供的 schema（`entryListSchema`、`userPatchesSchema`），确保 dump、patch 与真实加载行为一致，避免 YAML 方言漂移。
- 通过 `WeakMap<Context, Entry>`（如 `bootstrapIncludes`）在 Context 生命周期内缓存关键 Loader 节点，使 HMR 热重载能精确定位并更新根 Include 而不破坏其他层。
