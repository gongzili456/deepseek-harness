- 每个对外能力以 Cordis `Service` 子类形式暴露，并通过 `declare module '@deepseek-ai/cordis'` 向 `Context` 合并键（如 `apiProxy`、`webServer`、`directoryPicker`）。
- 配置对象统一使用 `@deepseek-ai/schemastery`（Zod）声明 `static Config` 并在构造函数中验证，保证部署参数可被 IDE 提示与运行时校验。
- API 边界采用 schema 与实现分离：每个领域目录包含同名 `.schema.ts`（Zod 类型/校验）与 `.ts`（RPC 处理器），由 `rpc-map.ts` 集中注册。
- 错误在 wire 层映射为稳定的 `{ code, message, details }` 结构（如 `RpcError`、`DirectoryPickerErrorCode`），内部异常不直接透传到客户端。
- 可插拔后端通过能力判别（discriminated union，如 `kind: 'native'|'browse'`）+ 抽象基类（`DirectoryPicker`）实现，消费者 switch on `capability().kind` 而非硬编码分支。
- HTTP 路由注册返回 disposer 函数，便于测试或热重载时撤销注册；重复注册 exact/prefix/upgrade 路径直接抛错以尽早发现冲突。
