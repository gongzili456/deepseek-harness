模块以 Cordis `Service` 为统一扩展点，按职责拆分为多个独立子包：
- `apiproxy/`：核心网关，`ApiProxyService` 通过 `createApiProxy` 将 `ctx.agentDefaultModel`、`sessions`、`workspaceRegistry`、`tools`、`settings`、`credentials`、`llm`、`subagents`、`sessionQuery` 等宿主能力聚合为传输无关的 RPC 接口；每个领域（sessions/goals/skills/settings/...）由成对的 `.schema.ts`（Zod 校验）与 `.ts`（实现）组成，并通过 `rpc-map.ts` 集中注册；`fetch/handler.ts` 与 `fetch/client.ts` 提供基于 `node:http` 的 carrier 对。
- `webserver/`：纯 `node:http` 路由容器，维护 exact/prefix 路由表、upgrade 路由表和单一 fallback seat，启动时立即 listen，所有未命中请求交由 fallback（通常由 `frontend-static` 认领）。
- `frontend-static/`：消费 `ctx.webServer.registerFallback` 提供 SPA dist 目录的静态文件服务，并注入 index.html 变换管线。
- `directory-picker/`：定义 `DirectoryPicker` 抽象服务及 `native`/`browse` 两种能力契约；`directory-picker-native/` 用原生对话框（含 win32 worker）实现 native 后端，`directory-picker-browse/` 提供浏览器内浏览后端，`directory-picker-auto/` 根据 `bindHost`、`SSH_*`、`DISPLAY`/`WAYLAND_DISPLAY`、平台与可选 Linux chooser 二进制在启动时解析出唯一后端并挂载。
- `plugin-inventory/`：暴露 `PluginInventoryGateway` Typert 远程服务，只读投影当前 Loader 插件条目状态。
依赖方向单向：`frontend-static` → `webserver`；`apiproxy` 仅通过类型边引用其他 dsh-* 包避免循环；各 picker 后端通过同一 seam 被 `apiproxy` 调用。
